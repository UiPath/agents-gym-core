# Reproducing ReAPO

How to reproduce the experiments of *Simplicity is Enough: ReAct Agents for Prompt Optimization*:
the data, the settings, and the agent version behind each table cell.

## Setup

```bash
GIT_LFS_SKIP_SMUDGE=1 git clone --recurse-submodules https://github.com/UiPath/agents-gym-core agents-gym-core
cd agents-gym-core
python3 scripts/check_dependency_policy.py
uv sync --locked --extra dspy --extra dev
cp .env.example .env    # pick a backend, add credentials
```

Start with one agent and a preview, then a bounded setup check:

```bash
uv run gym reproduce main-mini --agents aime_2025_agent --versions baseline-test --dry-run
uv run gym init aime_2025_agent
uv run gym eval --agents aime_2025_agent:baseline-test --models gpt-4.1-mini-2025-04-14 --num_runs 1 --max_datapoints 1 --experiment_name paper_smoke
```

The one-case run checks setup: its final summary should count 0 errored datapoints and
evaluations. To evaluate the full table with the paper's dataset and repeat counts:

```bash
for a in hotpotqa hover aime_2025_agent livebench_math ifbench papillon; do uv run gym init "$a"; done
uv run gym reproduce main-mini
```

The full public table prepares the shared retrieval index (1 GB, plus its 1.8 GB corpus) and makes paid model calls.
Use `--agents` / `--versions` to select a smaller experiment.

These commands evaluate the released prompt versions. To optimize prompts from the baseline,
use the optimizer scripts below.

A wheel works too (see the [README](../README.md#install)): without the `gepa-artifact`
submodule, `gym init` clones it at the pinned commit into `~/.cache/agents-gym-core`.

Use Python 3.11.5 through 3.13 and uv 0.13.4 or newer (CI uses uv 0.13.4). For CI's guarded
installation, use `python3 scripts/check_dependency_policy.py --sync --extra dspy --extra dev`.
The [dependency policy](guides/dependency-security.md) covers installation checks,
uv compatibility and dependency updates.

Scores go to `experiments/reproduce/<table>/final_score_per_agent.json` (`--output-dir`,
`--experiment-name`); a run with another number of runs or a call limit gets its own directory
(e.g. `transfer_10runs`, `agents-forced_12calls`). Reproduction runs in the testbed's
`fill_skip_run_errors` mode: rerunning a command fills missing outputs and evaluator results,
keeps a failed agent run as scored, reruns an evaluator that raised (a judge outage, say)
on the saved output, and reruns a run that failed on a model endpoint outage (connection,
timeout, rate-limit, credential or server error).
`gym reproduce` exits with code 1 while such runs remain. Use a new `--experiment-name` for a
fresh evaluation.

Some table cells share a prompt version, as listed by `gym reproduce`. AIME uses one GEPA
prompt for GEPA and GEPA-Merge, which are equivalent on its single-module program;
LiveBench-Math keeps each variant's released prompt. The GPT-4.1-mini Score-Only cells on
HotpotQA and LiveBench use `baseline-test`, the prompt selected by those optimization runs;
`gym reproduce tool-ablation` skips them, and their scores are the Baseline row of `main-mini`.
The σ_Trimmed LiveBench prompt is likewise the baseline prompt.

The PUPA side experiment in the frontier appendix, in which the optimizer received only the
aggregate score, has the versions `reapo__gpt-4.1-mini__aggregate-only-test` and
`reapo__gpt-5__aggregate-only-test`. On PUPA, the Opus run (`reapo__opus-4.6-test`) also received
only the aggregate score. Evaluate them with:

```bash
uv run gym reproduce frontier --agents papillon --versions reapo__gpt-4.1-mini__aggregate-only-test reapo__gpt-5__aggregate-only-test
```

To re-run their optimization, set `COACH_HIDE_EVALUATOR_FIELDS=1`, which leaves quality and
leakage out of the results the optimizer reads. The command runs the GPT-4.1 Mini optimizer; for
GPT-5 leave out `OPTIMIZER_MODEL`, for Opus set it to `anthropic.claude-opus-4-6-v1`:

```bash
COACH_HIDE_EVALUATOR_FIELDS=1 OPTIMIZER_MODEL=gpt-4.1-mini-2025-04-14 bash scripts/run_react_benchmarks.sh papillon
```

**Qwen models.** Qwen3.5-9B (`Qwen/Qwen3.5-9B`) runs with thinking off: every request sends
`chat_template_kwargs: {"enable_thinking": false}`. It is served by your own vLLM server or a
hosted OpenAI-compatible endpoint such as Fireworks (`QWEN_9B_VLLM_BASE_URL`, default
`http://localhost:8002/v1`, `QWEN_9B_VLLM_MODEL` and, for an endpoint that needs one,
`QWEN_9B_VLLM_API_KEY`); vLLM 0.18.0 serves it with the command below.
For `self-opt-122b`, configure your Qwen3.5-122B-A10B system model behind an
OpenAI-compatible endpoint (for example a Fireworks on-demand deployment of
`accounts/fireworks/models/qwen3p5-122b-a10b`, with `AGENTS_GYM_MODEL_BASE_URL` set to
`https://api.fireworks.ai/inference/v1`), set `AGENTS_GYM_MODEL_BASE_URL` and
`AGENTS_GYM_MODEL_API_KEY`, and give its model name in `QWEN_122B_MODEL` or with `--model`; on the
`langchain` backend an unregistered name goes to that endpoint while judges and embeddings keep
their own clients.

```bash
vllm serve Qwen/Qwen3.5-9B --served-model-name Qwen/Qwen3.5-9B --port 8002 \
  --dtype bfloat16 --max-model-len 131072 --max-num-seqs 64 --gpu-memory-utilization 0.85 \
  --enforce-eager --gdn-prefill-backend triton --trust-remote-code \
  --reasoning-parser qwen3 --enable-auto-tool-choice --tool-call-parser qwen3_coder \
  --limit-mm-per-prompt '{"image": 0, "video": 0}'
```

**PUPA's `untrusted_model`.** The model that receives the redacted request is the system model
unless `--models '{"model": "<system model>", "untrusted_model": "gpt-4.1-mini-2025-04-14"}'`
names another; GEPA's definition uses `gpt-4.1-mini`, the main tables' system model.

**Model serving.** Each response's `system_fingerprint`, where the provider reports one, is kept
in the run's `output.json`.

**Enterprise agents.** Their tools read data shipped with the repository (claim records,
customer-support responses, a calendar, a product catalog, the Chinook database), so no external
system is needed. Product Questions embeds its catalog with `text-embedding-3-large` and keeps the
index in `db_cache/product_questions_agent/` under the working directory, which later runs reuse;
delete it after switching the embedding endpoint. The forced-final-answer table (`agents-forced`)
uses the `basic:auto-graceful` loop with `UIPATH_AGENTS_GYM_LOOP_RECURSION_LIMIT` 6, or 12 for SQL and
Meeting Management: the 95th percentile of model calls in successful runs with a 30-call
budget. That loop also forces the final answer once the same tool call (same tool and
arguments) has been made `max(limit // 3, 2)` times: 2 at limit 6, 4 at 12. Either way it then
makes one more call that offers only `end_execution`. The default `basic`
loop enforces its call limit (20 by default) with a `TERMINATION_MAX_ITERATIONS` run error.
On Customer Support Triage both optimizers kept the baseline prompt, so `baseline-test`,
`gepa__gpt-5-test` and `reapo__gpt-5-test` are the same prompt and the paper reports the shared
evaluation in all three rows.

The paper agents' default prompts (`base`, `train`, `test`) are the released GPT-5 ReAPO prompts;
the paper's unoptimized rows are the `baseline*` versions.

## Running

| Script | Does |
|---|---|
| `scripts/run_react_benchmarks.sh [agents]` | ReAPO on the public benchmarks (override `OPTIMIZER_MODEL`, `ROUNDS`, `LOOP_MODEL`, `SKILL`, `ABLATION`) |
| `scripts/run_react.sh [agents]` | ReAPO on the enterprise agents |
| `scripts/run_gepa.sh [agents]` | GEPA-DSPy on the enterprise agents (budget 5 x train size) |

The optimizers edit an agent's prompt files in place; the scripts snapshot `prompts/` and
`versions.yaml` and restore them afterwards, also on Ctrl-C (`KEEP_OPTIMIZED_PROMPTS=1` keeps the
edits). Each round's prompts and scores, with `run_metadata.json`, stay in the optimizer
workspace `tmp_<name>_<agent>_.../round_*`; GEPA's evolved prompts go to
`experiments/evolved_prompts/`. `CONTINUE=1` in the scripts (`-c` in `gym optimize`) resumes an
interrupted ReAPO run after its last scored round; finished runs are skipped.

### The ablations

`prompt_optimization/skills/` holds the paper's three skill prompts: `full` (σ_Full,
the default), `trimmed` (σ_Trimmed) and `tool-free` (σ_Ablate, the simplified skill of the
score-only and macro ablations). The loader removes their sentence about continuing from a
starting round; the paper prints the resulting skill text.
`--ablation` (`ABLATION` in the scripts) removes the Results Analysis tools, excluding the
aggregate-score tool `list_experiments`: `score-only` keeps only `list_experiments`, so the optimizer
sees the aggregate score of each run; `macro` also keeps `get_full_results`. Both hide the eval-set
files.
Every ablation ran 5 rounds (6 on IFBench) with a GPT-4.1-mini system model. The `score-only` and `macro`
ablations use σ_Ablate (`SKILL=tool-free`); `Full` uses the default `full`:

| Ablation | Command (add the benchmarks of the table) |
|---|---|
| Tools, GPT-5 optimizer | `SKILL=tool-free ABLATION=score-only bash scripts/run_react_benchmarks.sh ...` (`macro` likewise) |
| Tools, GPT-4.1-mini optimizer | `OPTIMIZER_MODEL=gpt-4.1-mini-2025-04-14 SKILL=tool-free ABLATION=score-only bash scripts/run_react_benchmarks.sh ...` |
| Tools, enterprise agents | `SKILL=tool-free MODEL=gpt-4.1-mini-2025-04-14 ABLATION=score-only bash scripts/run_react.sh` (Full: without `SKILL` and `ABLATION`) |
| Skill prompt | `SKILL=trimmed bash scripts/run_react_benchmarks.sh ...` |

## Cost and the PUPA decomposition

Each datapoint run writes `cost.json` next to its `output.json`: input, output and cached tokens,
calls and USD, in total, per model and for the loop's own model, priced by
`MODEL_COST_PER_MILLION` in `runtime/cost_tracking.py` (providers' list prices as of October
2026) unless the UiPath gateway reports a cost; LLM judges are not counted. The testbed averages
the per-run sums into the `cost` field of `final_score_per_agent.json`
([run output formats](guides/run-output-formats.md)). A ReAPO run's `run_metadata.json` records
`optimizer_cost` (the optimizer model's own calls, summed over `-c` sessions), `eval_cost` (the
train-split runs it started), their sum `total_cost_usd`, `total_duration_s`, `best_round` and
`time_to_best_round_s`; `round_NNN/round_stats.json` lists each round's evaluation runs. Test
evaluation is in neither. The paper's optimization cost recomputes these token counts at list
prices without the cached-input discount; `total_cost_usd` applies the cached rate, the paper's
parenthesised figure.

PUPA's score is `(quality + (1 - leakage)) / 2`. Each `PapillonEvaluator` result keeps both parts
in `details`: `quality`, the judge's verdict that the response is at least as good as the
reference, and `leakage`, the fraction of the datapoint's PII units found in the request sent to
the untrusted model; an empty response counts as `quality: false`, `leakage: 1.0`.
